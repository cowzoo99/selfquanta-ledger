# SelfQuanta 快速生产部署设计

日期：2026-10-29

## 1. 目标

把当前已通过自动化测试的协同内账系统尽快上线，先供公司自用和少量受邀人员内部使用，同时为后续多个小项目、国内公开访问和海外项目保留平滑扩展路径。

首期成功标准：

- 代码存在可靠 Git `origin`，提交可追溯且不含生产秘密；
- 系统运行在腾讯云上海地域，业务数据留在中国大陆；
- 备案完成前，受邀人员可通过加密私网访问；
- 备案完成后，通过 `https://ledger.selfquanta.com` 公开访问；
- 服务器重启后服务、数据库和附件仍然可用；
- 加密备份可以在隔离环境中完成一次真实恢复；
- 账套管理员和账务查看者权限边界在生产环境中通过验收。

## 2. 已确认条件

- 备案主体：杭州逆熵云人工智能理论算法软件有限责任公司。
- 母品牌：SelfQuanta。
- 拟注册主域名：`selfquanta.com`，最终可用性以腾讯云域名购买页为准。
- 当前用户规模：公司自用及少量朋友内部使用。
- 当前数据规模：较小，但财务数据必须持久保存和可恢复。
- 后续可能同时运行其他小项目，也可能新增海外项目。
- 每个正式收费客户仍使用独立部署，不共享内账数据库或附件卷。

营业执照编号、负责人证件、服务器密码、Git 凭据、TLS 私钥和备份密钥不得进入本仓库。

## 3. 方案选择

采用“上海主节点先内部上线，ICP备案并行，备案后开放公网”的两阶段方案。

不使用 CloudBase 云托管承载本系统。CloudBase 不支持 Docker Compose，也不能在云托管中部署 MariaDB、Redis 等有状态服务；当前 Frappe/ERPNext 系统依赖数据库、两个 Redis、后台队列、调度器、WebSocket 和持久化附件卷，强行迁移会变成大规模无状态改造。

不把真实财务数据放入临时演示容器或不可持久化的免费环境。

## 4. 基础设施

### 4.1 首台服务器

- 产品：腾讯云轻量应用服务器；
- 地域：上海，随机可用区；
- 操作系统：Ubuntu 24.04 LTS；
- 起步规格：4 核 CPU、8 GB 内存、120 GB SSD、10 Mbps；
- 实例与域名使用同一企业实名认证腾讯云账号购买；
- 启用腾讯云登录保护、费用告警和快照能力。

2 核 4 GB 只作为短期试验下限，不作为本方案的生产规格。Frappe、ERPNext、MariaDB、Redis、队列和镜像构建并行运行时需要保留内存余量。

### 4.2 主机目录

服务器统一使用以下结构：

```text
/srv/selfquanta/
  edge/                 # 未来统一域名入口
  ledger/               # 当前协同内账项目
  projects/<name>/      # 后续低流量小项目
/etc/selfquanta/ledger/ # 运行秘密、证书和环境文件
/var/backups/selfquanta/ledger/
```

每个项目使用独立 Compose 项目名、网络、数据库卷、附件卷、日志和备份，不共享数据库账号或运行秘密。

### 4.3 容量边界

首台服务器可以承载当前内账和少量低流量小项目。监控满足任一条件时停止继续混部并新增服务器：

- 持续内存使用超过 75%；
- 系统盘使用超过 70%；
- 持续 CPU 使用超过 60%；
- 任一项目需要独立安全边界、对外 SLA 或大量后台任务。

海外项目后续新增新加坡或其他目标用户就近节点，不把国内主节点跨境搬迁。

## 5. Git 与镜像发布

### 5.1 GitHub origin

最快路径采用 GitHub 公共仓库：

```text
https://github.com/cowzoo99/selfquanta-ledger.git
```

原因：现有固定版本镜像构建只接受不含凭据的 HTTPS Git origin。仓库只保存源代码、脱敏测试样本和运维脚本，不保存客户数据、服务器地址、密码、密钥、证书或备份。

如果后续必须改为私有仓库，需单独设计 BuildKit 凭据或镜像仓库发布流程，不在首期快速上线范围内。

### 5.2 发布标识

- 首次生产候选使用当前 `main` 的精确提交 SHA；
- 生产镜像标签使用完整 40 位 Git SHA，不使用 `latest`；
- 完成启动、重启、备份和恢复验收后，才创建 `v0.1.0` 标签；
- 服务器只运行已验证的固定镜像，不直接运行未提交工作树。

## 6. 网络与访问

### 6.1 备案前内部访问

- 在服务器上建立 WireGuard 私网；
- 只向受邀设备分发独立客户端配置；
- 内账 Web 服务只允许从 WireGuard 网段访问；
- 临时 TLS 使用内部证书，传输同时受 WireGuard 加密保护；
- 不以未备案域名绕过中国大陆接入要求，不公开真实账务系统。

### 6.2 备案后公开访问

- `ledger.selfquanta.com` 解析到上海服务器固定公网 IP；
- 使用 ACME 自动签发并续期公开 TLS 证书；
- HTTP 强制跳转 HTTPS；
- 仅开放 SSH、HTTP、HTTPS 和 WireGuard 必需端口；
- 数据库、Redis、后端、队列、调度器和 WebSocket 内部端口不对公网发布；
- SSH 使用密钥登录，关闭密码登录和 root 远程登录。

后续项目使用独立子域名，并由统一边缘代理按域名路由，不抢占同一 80/443 端口。

## 7. 应用部署

继续使用仓库现有固定版本部署链：

- Frappe `v16.52.0`；
- ERPNext `v16.52.1`；
- MariaDB `11.8`；
- Redis `8.2-alpine`；
- frappe_docker `v4.1.1`、commit `d84154ae23ab7ae756dfe942e3f24dcd70d1fbda`。

部署步骤：

1. 安装 Docker Engine、Compose v2、Git、PowerShell 7 和必要系统工具。
2. 克隆 `selfquanta-ledger` 与固定版本 `frappe_docker`。
3. 在仓库外生成数据库、站点管理员、备份和内部 TLS 秘密。
4. 运行 `infra/test-config.ps1` 和 Compose 配置检查。
5. 构建以 Git SHA 标记的不可变应用镜像。
6. 创建单一 Frappe 站点并安装 ERPNext 与 `internal_ledger`。
7. 启动数据库、Redis、后端、前端、WebSocket、队列和调度器。
8. 设置时区 `Asia/Shanghai`、本位币 CNY、会计年度和企业资料。
9. 禁用公开注册，创建具名管理员和只读成员。

## 8. 备份与恢复

备份必须同时包含：

- MariaDB 站点数据库；
- public/private 附件；
- 站点配置中恢复所需的非秘密元数据；
- 加密后的备份清单与校验值。

策略：

- 每日执行一次应用级加密备份；
- 本机只保留短期副本；
- 加密副本上传腾讯 COS，使用独立目录和最小权限凭据；
- 每周创建服务器快照作为辅助保护，但快照不替代应用级备份；
- 首次上线必须在隔离 Compose 项目中恢复数据库和附件，并验证登录、报表及一份附件读取。

## 9. 安全边界

- Git 仓库和镜像不得包含任何生产秘密或真实账单；
- 运行秘密文件权限为 `0600`，仅必要服务可读取；
- 服务器运维账号与应用账号分离；
- 账套管理员、账务查看者继续由服务端权限强制执行；
- 登录、成员变更、导入、审核、过账、冲销和恢复均保留审计证据；
- 开启系统安全更新、登录失败限制和基础日志轮转；
- 不安装宝塔等额外管理面板，减少攻击面和资源占用。

## 10. 实施阶段

### 阶段 A：账号与购买

由所有者完成腾讯云企业实名认证，购买 `selfquanta.com` 和上海轻量服务器，并提供服务器公网 IP 与一次性初始化访问方式。

### 阶段 B：代码发布

创建 GitHub 公共仓库，配置 `origin`，推送 `main`，确认远程提交与本地 HEAD 一致。

### 阶段 C：内部生产上线

完成主机加固、WireGuard、镜像构建、站点初始化、服务启动和内部访问验证。

### 阶段 D：可靠性验收

完成重启持久性、权限、加密备份、隔离恢复、日志和资源监控检查。全部通过后创建 `v0.1.0`。

### 阶段 E：备案与公网

提交企业 ICP 备案。备案通过后设置 DNS、公开 TLS、边缘路由和公网验收；WireGuard 保留为运维和故障访问通道。

## 11. 验收清单

- GitHub `main` 与生产镜像 SHA 对应；
- 公网仅暴露批准端口；
- 管理员可以登录、导入脱敏样本、审核和过账；
- 查看者可以读取但不能调用任何写接口或下载原始账单；
- 临时密码首次登录强制修改；
- 容器和整机重启后数据、附件和会话策略符合预期；
- 备份不含明文密码，COS 中只有加密副本；
- 隔离恢复成功且不覆盖生产站点；
- 备案前系统不向公网提供未备案域名服务；
- 备案后 `ledger.selfquanta.com` 使用有效 HTTPS 证书。

## 12. 非目标

首期不实施：

- 多客户共享数据库的多租户 SaaS；
- Kubernetes、CloudBase 无状态重构或复杂 CI/CD；
- 跨地域自动容灾；
- 自动购买云资源、域名或代替所有者提交实名认证资料；
- 将多个正式收费客户长期混部在同一服务器；
- 高并发容量承诺。
