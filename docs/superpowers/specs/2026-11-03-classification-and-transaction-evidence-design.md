# SelfLedger 自动分类与逐笔凭证附件设计

日期：2026-11-03
状态：已获产品规格批准，待书面复核
适用范围：单公司、单账套、管理员编辑、企业成员只读

## 1. 背景与问题定位

当前导入流程已经能够识别银行流水、检测重复并执行分类规则，但待办中心仍把两类数据混在“待分类”中：

1. 确实没有匹配规则、需要人工分类的流水；
2. 导入后才新增规则，重新计算时已经匹配、但尚未生成凭证草稿的历史流水。

第二类流水页面显示“已匹配”，却仍要求人工点击“批量生成凭证”，造成“自动分类没有执行”的体验。同时，主列表使用内部随机编号作为主要操作文案，借贷科目也不够直观。

此外，每笔流水需要长期保存业务说明和原始佐证材料，并在分类、凭证草稿、审核、过账各阶段持续可见。

## 2. 目标

- 进入自动分类步骤时，系统自动处理“已匹配但未生成草稿”的流水，并将其移入“凭证草稿”。
- 未匹配或规则冲突的流水留在自动分类步骤，明确告诉用户为什么需要人工处理。
- 每笔流水明确显示业务分类、匹配依据、借方科目、贷方科目和金额。
- 每笔流水可添加文字、简单表格、图片及常见办公文档作为备注和佐证。
- 管理员可编辑；企业成员只能查看和下载。
- 保留重复复核、分页、上一步/下一步、批量审核和正式过账流程。

## 3. 非目标

- 不从备注附件中做 OCR、内容识别或自动分类。
- 不自动审核或自动过账；自动化仅到“生成凭证草稿”为止。
- 不把系统开放到公网；访问方式仍为现有 WireGuard 内网加账号密码。
- 不改变原始银行流水文件的管理员专属访问权限。
- 不在浏览器内预览 Word、Excel 等办公文档；此类文件只提供安全下载，图片可预览。

## 4. 自动分类流程

### 4.1 五步流程保持不变

1. 导入识别
2. 重复复核
3. 自动分类
4. 凭证草稿
5. 审核过账

页面继续保留分页，并在页面底部固定显示“上一步”和“下一步”。用户不需要使用浏览器返回键完成流程。

### 4.2 进入自动分类时的处理

管理员进入第 3 步或刷新该步骤时，前端调用一次幂等的“处理待分类流水”接口。服务端逐笔执行：

- 已有凭证草稿：不重复创建，返回现有状态；
- 唯一规则匹配：创建平衡的凭证草稿并移入第 4 步；
- 没有匹配规则：留在第 3 步，标记“需要人工分类”；
- 多条规则冲突：留在第 3 步，标记“规则冲突”；
- 疑似重复且未完成复核：不分类，保持只读并引导到第 2 步；
- 处理失败：保留在第 3 步并显示中文失败原因，不吞掉异常。

该接口必须可重复调用，重复进入页面不会生成重复草稿。

只读成员打开第 3 步时不触发写操作，只看到最近一次处理结果。

### 4.3 处理结果提示

自动处理完成后，页面顶部显示一次中文汇总：

- 已自动分类并生成草稿：N 笔
- 需要人工分类：N 笔
- 规则冲突：N 笔
- 失败：N 笔

若存在失败项，用户可在对应流水查看错误原因；成功项不再留在“待分类”列表。

### 4.4 人工分类界面

未匹配流水默认自动选中当前分页的第一笔，并直接展示中文快捷分类：

- 办公费
- 差旅费
- 采购支出
- 经营收入
- 手续费
- 股东投入
- 账户转账
- 其他

选择快捷分类后，页面立即展示将要生成的借方、贷方科目。管理员仍可展开“修改会计科目”进行精确调整。提交前必须满足：

- 借贷金额相等；
- 借方和贷方科目不同；
- 科目有效且属于当前公司；
- 会计期间允许记账。

提交后只生成待审核凭证草稿，不自动审核或过账。

### 4.5 分类结果展示

流水详情使用业务信息作为主内容，固定显示：

- 业务分类
- 匹配状态与中文原因
- 借方科目名称和编码
- 贷方科目名称和编码
- 金额
- 交易对象、摘要、日期、资金账户

内部流水 ID、批次 ID 和规则 ID 收入折叠的“技术信息”区域，不再作为按钮或主标题。

## 5. 逐笔备注与佐证附件

### 5.1 用户界面

每笔流水详情增加“备注与附件”区域，在第 2 至第 5 步及会计中心查看同一份内容，不复制文件。

管理员可以：

- 编辑富文本备注；
- 插入简单表格；
- 上传、查看、下载和删除附件；
- 在流水过账后继续补充资料，所有修改仍需记录审计日志。

企业成员可以：

- 查看备注；
- 预览图片；
- 下载允许访问的附件；
- 不可新增、修改或删除。

### 5.2 文件限制

允许格式：

- 图片：PNG、JPG、JPEG、WEBP
- 文档：PDF、DOC、DOCX、TXT
- 表格：XLS、XLSX、CSV

限制：

- 单个文件不超过 10 MB；
- 每笔流水最多 10 个附件；
- 所有附件使用私有文件存储；
- 禁止 HTML、脚本、可执行文件和未允许的扩展名；
- 服务端校验扩展名、声明的 MIME 类型，并在可行时校验文件特征，不能只信任浏览器上报值；
- 文件名显示给用户前必须转义，下载响应不得以内联 HTML 执行。

图片可在页面内预览；PDF、Word、Excel、CSV、TXT 均以下载为主，避免增加复杂的在线预览组件。

### 5.3 数据模型

新增 `Ledger Evidence` 文档，每笔 `Imported Transaction` 最多对应一条：

- `imported_transaction`：必填、唯一、只读关联；
- `company`：从流水带入，只读，用于权限校验；
- `note_html`：经过服务端清洗的富文本，支持文字、列表和简单表格；
- 标准创建人、创建时间、修改人、修改时间字段。

附件继续使用 Frappe `File` 文档，关联到 `Ledger Evidence`，并强制 `is_private = 1`。不将文件内容写入流水表，也不为不同阶段复制附件。

原始导入文件继续关联 `Internal Ledger Source File`，沿用现有管理员专属权限；它与逐笔佐证附件是两个不同的访问域。

## 6. API 与数据流

### 6.1 自动分类

新增或复用一个管理员专属幂等接口，处理当前公司“已匹配但无草稿”的流水。响应返回数量汇总和逐笔失败信息。接口必须复用现有分类与凭证草稿服务，不另写第二套规则引擎。

页面加载顺序：

1. 管理员进入自动分类页；
2. 调用自动处理接口；
3. 重新读取各步骤数量与当前页数据；
4. 显示汇总提示；
5. 自动选中第一个仍需人工处理的项目。

只读成员跳过第 2 步。

### 6.2 备注与附件

提供最小化接口：

- 读取某笔流水的备注与附件清单；
- 管理员保存备注；
- 管理员上传附件；
- 管理员删除附件；
- 有权限用户下载附件。

每个接口都必须从当前登录用户和关联流水重新校验公司及角色，不能仅依赖前端隐藏按钮或客户端传来的公司字段。

## 7. 权限与安全

### 7.1 管理员

- 可触发自动分类处理；
- 可人工分类、生成草稿、审核和过账；
- 可创建、更新、删除备注与附件；
- 可读取原始导入文件和逐笔佐证附件。

### 7.2 企业成员

- 可查看流程状态、流水、凭证、报表、备注和逐笔佐证附件；
- 可下载自己所属公司流水的逐笔佐证附件；
- 不可触发任何会写数据的接口；
- 不可读取原始导入文件。

### 7.3 通用约束

- 所有查询按当前单公司账套过滤；
- 私有文件下载必须经过会话认证和服务端权限判断；
- 不生成永久公开 URL；
- 富文本在保存和显示时均按允许标签清洗，允许基础段落、列表、链接和简单表格，禁止脚本、事件属性、iframe 和危险 URL；
- 删除附件只删除指定 `Ledger Evidence` 下的文件，不能通过任意文件名或文件 ID 越权删除其他文件。

## 8. 审计与生命周期

审计日志新增以下中文可识别操作：

- 自动分类处理；
- 人工分类并生成草稿；
- 更新流水备注；
- 上传佐证附件；
- 删除佐证附件。

日志记录操作人、时间、流水、动作和必要的结果摘要，不记录附件正文。备注变更至少记录“已更新”和操作人；不要求保存完整富文本历史版本。

过账后仍可补充备注和附件，但不得借此修改已过账凭证的科目、金额或会计期间。删除附件为显式管理员操作且必须留审计记录。

## 9. 兼容与迁移

- 新文档类型和字段通过应用迁移创建；旧流水无需批量回填证据记录，第一次保存备注或附件时按需创建。
- 已有凭证草稿和已过账流水不重新分类。
- 仅处理“尚无草稿、非重复阻塞、当前分类结果唯一匹配”的历史流水。
- 现有分类规则、重复检测、原始文件权限和凭证编号保持不变。
- 前端继续使用现有统一产品入口，不增加第二个网站或第二套登录。

## 10. 验收标准

### 10.1 自动分类

- 导入一批包含匹配、未匹配、冲突和重复流水的数据后，各项进入正确步骤。
- 新增规则后再次进入第 3 步，历史“已匹配但无草稿”的流水自动生成且只生成一份草稿。
- 匹配成功的流水从第 3 步消失并出现在第 4 步。
- 未匹配流水自动选中并显示中文快捷分类、明确借贷科目和金额。
- 冲突与失败均显示中文原因。
- 只读成员访问不会产生草稿或其他写操作。
- 不发生自动审核或自动过账。
- 分页、上一步和下一步持续可用。

### 10.2 备注与附件

- 管理员可在任一流程阶段为同一流水编辑文字、简单表格并上传允许文件。
- 图片可预览，其他允许文件可下载。
- 超过 10 MB、第 11 个文件或不允许格式均被服务端拒绝并显示中文提示。
- 企业成员可查看和下载逐笔佐证，但无法保存备注、上传或删除附件。
- 企业成员仍不能读取原始导入文件。
- 越权访问其他流水附件、伪造公司字段和直接调用写接口均被拒绝。
- 过账后补充或删除佐证不会改变已过账凭证。
- 更新备注、上传和删除附件均产生审计日志。

### 10.3 回归与部署

- 后端单元测试覆盖幂等分类、权限、文件限制、富文本清洗和附件归属。
- 前端测试覆盖自动处理汇总、人工分类、分页导航和附件交互。
- 既有重复复核、分类规则、凭证草稿、审核过账和报表测试继续通过。
- 在测试环境完成一次“导入到过账”的端到端验收，再部署生产。
- 生产部署前备份；部署后验证登录、导入、分类、附件权限和健康检查；保留可执行的回滚步骤。

## 11. 完成定义

只有同时满足以下条件，功能才算完成：

1. 自动分类不再把已匹配项目滞留在第 3 步；
2. 用户能在页面直接看懂分类去向和专业借贷分录；
3. 每笔流水具备符合权限和限制的备注与附件能力；
4. 只读成员无法产生任何写操作，也无法访问原始导入文件；
5. 自动化测试、端到端验收和生产验证均有可复查结果；
6. 没有新增第二套网站、登录或分类逻辑。
