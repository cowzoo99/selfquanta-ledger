# SelfLedger 面向公众的小微企业 ERP 平台设计规格

- 状态：正式规格已批准，进入实施计划阶段
- 日期：2026-11-06
- 产品暂定名：SelfLedger ERP
- 目标版本：8 周邀请制公开测试版
- 目标客户：1–30 人商贸及一般服务型小企业
- 开发资源：产品负责人 + Codex，无全职技术团队
- 首轮规模：3–5 家邀请制免费试点企业

## 1. 文档目的

本文件是 SelfLedger 从“单公司智能内账工具”升级为“可面向公众运营的小微企业 ERP SaaS”的立项、产品、架构、测试、部署和商业化基线。

后续需求、代码、测试、部署和验收均以本文件为上位依据。新增需求不得直接插入当前迭代，必须先评估对范围、数据、权限、兼容性和交付周期的影响。

本文件不授权立即修改生产系统。实施前仍需编写独立的逐步实施计划，并经过用户批准。

## 3. 产品愿景与边界

### 3.1 产品愿景

让没有专职 ERP 实施团队、会计或信息化人员的小公司，也能通过导入已有流水、发票和业务资料，完成销售、采购、库存、费用、工资与财务联动，并生成标准账簿、经营报表和报税格式材料。

### 3.2 核心价值

1. 导入优先：允许企业从已有文件开始，而不是先配置数十天。
2. 业财一体：正式业务单据与库存、资金、往来和总账使用同一份数据。
3. 小白可用：用户按“我要做什么”进入任务，不要求先理解 ERP 内部术语。
4. 专业可控：会计、管理员仍可进入高级模式完成专业处理。
5. 数据隔离：每个客户独立数据库、文件、密钥和备份。
6. AI 可选：AI 负责解释和建议，不能绕过权限、审批和会计规则。
7. 可退出：客户可以导出自己的数据，不能依靠数据锁定强迫续费。

### 3.3 8 周首版不包含

- 直接向税务系统提交申报；
- 银行账户实时直连；
- 全部电商平台正式 API；
- 微信小程序和原生 App；
- 完整生产制造、BOM、MRP 和工单；
- 多模型调度；
- 多节点高可用和多地域双活；
- 客户自助支付和完全自动开通；
- 99.99% SLA 或 7×24 人工支持。

这些能力可以预留接口，但不能阻塞 8 周邀请制版本。

## 4. 市场与竞品结论

### 4.1 竞品定位

| 产品 | 优势 | SelfLedger 的差异方向 |
|---|---|---|
| 金蝶 AI 星辰 | 中国财税、票税银、品牌与服务网络 | 更低成本、数据独立、导入优先和可解释 AI |
| 畅捷通好业财 | 小微业财一体成熟、实施经验丰富 | 更简单的上手路径、独立租户和开放数据 |
| 管家婆 | 进销存简单、零售批发认知强 | 更强财务自动化、现代协作和统一 AI |
| Odoo | 模块数量、生态和国际化成熟 | 中国本地化、按企业收费和低学习成本 |
| ERPNext 原版 | 开源、模块完整、可自托管 | 统一中文产品层、托管运维、连接器和小白流程 |
| 单点记账软件 | 简单且便宜 | 销售、采购、库存、项目和人事与财务联动 |

### 4.2 竞争策略

SelfLedger 首年不以“模块数量最多”为目标，而以以下体验取胜：

- 注册或初始化后，当天得到第一张可信经营报表；
- 导入已有资料即可开始；
- 普通员工、小老板和专业会计共用一套数据；
- 按企业套餐收费，避免小微企业因为增加普通成员而承担高额许可费；
- 客户拥有独立数据空间和数据导出权；
- AI 给出依据、置信度和影响范围，写操作必须确认。

## 5. 开源底座与技术选型

### 5.1 采用

| 项目 | 用途 | 结论 |
|---|---|---|
| Frappe Framework v16 | 用户、权限、数据模型、工作流、API、后台任务和多站点 | 核心底座 |
| ERPNext v16 | 财务、销售、采购、库存、内置 CRM、项目和报表 | 核心业务 |
| Frappe HRMS v16 | 员工、考勤、请假、报销和工资 | 首版安装 |
| 现有 internal_ledger | 导入、OCR、重复检测、分类、凭证、过账和证据 | 保留并扩展 |
| frappe_docker | 生产镜像和 Docker Compose 部署 | 生产部署基础 |
| Frappe Press | 多站点、备份、更新和计费控制台参考 | 只借鉴，不整套引入 |

### 5.2 暂不采用

- 不迁移到 Odoo；迁移会重写现有智能记账和全部数据联动。
- 不安装独立 Frappe CRM；首版使用 ERPNext 内置 CRM，避免形成第二套 SPA 交互。
- 不安装 Insights 和 Helpdesk 到客户站点；先使用 ERPNext 报表，平台客服后续单独建设。
- 不使用 Kubernetes；3–5 家试点不需要该复杂度。
- 不建立微服务集群；优先采用 Frappe 单体模块化和后台任务。

### 5.3 版本策略

- 实施前锁定 Frappe、ERPNext、HRMS 的具体 v16 补丁版本；
- 不自动追随每周上游更新；
- 开发、预发布和生产使用同一应用镜像；
- 大版本升级单独立项；
- 升级前备份，先在预发布和单个试点 Site 验证；
- 保留上一镜像和可恢复备份。

### 5.4 应用结构

```text
Frappe Framework
├── ERPNext
├── Frappe HRMS
└── internal_ledger（产品显示 SelfLedger ERP）
    ├── intelligent_import
    ├── duplicate_review
    ├── classification
    ├── accounting_and_tax
    ├── china_localization
    ├── connectors
    ├── unified_ui
    └── optional_ai
```

首版不为每个模块创建独立应用。技术包名 `internal_ledger` 暂时保留，避免为改名破坏数据库迁移、接口和生产部署。

## 6. 多租户与客户隔离

### 6.1 隔离单位

一个客户企业对应一个 Frappe Site：

- 独立数据库；
- 独立数据库账号；
- 独立站点配置；
- 独立私有和公开文件；
- 独立接口密钥；
- 独立加密备份；
- 独立域名或子域名。

禁止在同一 Site 中承载互不相关的外部客户公司。

### 6.2 试点拓扑

```text
HTTPS 入口
    │
反向代理、限流、域名路由
    │
统一应用镜像
    ├── Site A / DB A / Files A / Backup A
    ├── Site B / DB B / Files B / Backup B
    └── Site C / DB C / Files C / Backup C
```

### 6.3 独立服务器升级

客户升级专属服务器时迁移整个 Site，包括数据库、文件、配置和加密备份。产品代码、域名规则、数据模型和用户体验不变。

### 6.4 平台支持访问

- 平台运营账号默认看不到客户业务数据；
- 技术支持需要客户授权、限时访问和审计记录；
- 运营控制台只保存客户、域名、版本、套餐、健康和备份元数据；
- 禁止复制客户账务数据到运营控制台。

## 7. 企业用户端功能架构

### 7.1 一级模块

1. 企业首页
2. 智能导入中心
3. 客户与 CRM
4. 销售管理
5. 采购管理
6. 商品与库存
7. 财务与税务
8. 费用报销
9. 项目协作
10. 人事工资
11. AI 助手
12. 企业设置

### 7.2 企业首页

按角色显示：

- 待审批、待收款、待付款；
- 库存不足、临期和负库存；
- 收入、支出、利润和现金余额；
- 应收、应付和逾期；
- 本月记账和结账进度；
- 缺少的发票、附件和银行流水；
- 工资、合同和项目到期提醒；
- AI 经营摘要。

首页卡片必须进入对应待办，不得只展示不可操作的图表。

### 7.3 智能导入中心

支持银行、微信、支付宝、回单、发票、PDF、JPG、PNG、Excel、CSV 和手工录入。

统一流程：

```text
上传识别
→ 重复复核
→ 自动分类
→ 凭证草稿
→ 审核过账
```

重复检测组合使用日期、交易双方、金额、方向、账号尾号、流水号、发票号、文件指纹和相似摘要。疑似重复进入人工复核；确认重复后不计入待过账总数，但保留审计记录。

### 7.4 CRM 与销售

CRM 使用 ERPNext 正式客户主档，包含线索、客户、联系人、跟进、销售机会和预计金额。

销售链路：

```text
线索 → 客户 → 报价 → 销售订单 → 发货 → 销售发票 → 收款 → 银行匹配 → 会计凭证
```

发货减少库存；发票形成收入、税额和应收；收款减少应收并增加资金账户；退货和退款形成反向业务及会计记录。

### 7.5 采购

```text
采购需求 → 采购订单 → 收货入库 → 采购发票 → 付款 → 银行匹配 → 会计凭证
```

支持分批收货、分批开票、分批付款、采购退货和供应商往来。

### 7.6 商品与库存

- 商品、服务、单位、规格和条码；
- 仓库和库位；
- 期初库存；
- 入库、出库、调拨和盘点；
- 销售占用、采购在途和可用量；
- 安全库存、批次、有效期和序列号；
- 库存估值、成本调整和库存明细账。

服务企业可以关闭库存，只使用服务项目。

### 7.7 财务与税务

日常会计：

- 会计科目、记账凭证、收付款凭证；
- 会计分录、现金和银行日记账；
- 总账、明细账和科目余额表；
- 应收、应付和银行对账；
- 固定资产和折旧；
- 期末结转、反结账和冲销审批。

财务报表：

- 资产负债表；
- 利润表；
- 现金流量表；
- 试算平衡表；
- 收支变动明细；
- 客户和供应商往来账；
- 项目利润表；
- 部门和费用分析。

月末结账依次检查未分类流水、疑似重复、待审核凭证、银行余额、往来、负库存、发票、工资、折旧、损益结转和借贷平衡。

报税材料中心生成账簿、报表、发票汇总、收入成本费用、工资、固定资产、银行核对及增值税和企业所得税辅助底稿。首版只显示“材料已生成”，不得声称“申报成功”。

### 7.8 费用报销

```text
员工填报 → 上传发票/回单 → OCR → 费用分类 → 审批 → 财务复核 → 付款 → 自动凭证
```

支持多级审批、项目/部门/成本中心归集、借款核销、批量付款和完整附件审计。

### 7.9 项目协作

项目、阶段、任务、成员、工时、进度、合同、附件、采购、报销、人工成本、收入、预算和利润必须复用销售、采购、报销和工资正式数据，不建立孤立项目账。

### 7.10 人事工资

```text
员工档案 → 考勤/请假/加班 → 工资项目 → 工资计算 → 审核 → 工资条 → 付款 → 财务凭证
```

首版包含部门、岗位、入转离、合同提醒、考勤、请假、加班、工资结构、工资批次、工资条、工资表和个税社保基础数据导出。

### 7.11 企业成员和角色

首版角色：企业所有者、企业管理员、财务主管、会计、出纳、销售、采购、仓库、HR、项目负责人、审批人和只读成员。

权限原则：

- 制单和审核可分离；
- 出纳不能擅自修改已审核科目；
- 销售不能查看全公司工资；
- HR 不能查看无权限银行流水；
- 只读成员没有服务端写权限；
- 批量修改、导出、删除和冲销全部审计。

### 7.12 附件和审计

每张单据和每笔账支持文本、图片、PDF、Word、Excel、表格明细和原始文件。审计包含创建、修改前后、审核、过账、取消、冲销、删除原因、AI 建议和来源批次。

正式财务数据不能无痕删除。受控删除或冲销必须同步业务单据、分录、总账和报表。

## 8. 数据唯一来源与联动

ERPNext 正式 DocType 是唯一正式业务和会计数据源：

- Customer、Supplier、Item；
- Quotation、Sales Order、Delivery Note、Sales Invoice；
- Purchase Order、Purchase Receipt、Purchase Invoice；
- Stock Entry、Stock Ledger Entry；
- Payment Entry、Journal Entry、GL Entry；
- Project、Task；
- Employee、Attendance、Salary Slip。

SelfLedger 自定义对象只保存原始材料、识别过程、复核、分类建议、凭证草稿和关联关系，不维护第二套正式总账。

连接器和重试必须幂等，重复同步不能产生重复业务单据。

## 9. 统一 UI 与交互

### 9.1 唯一产品外壳

一个登录、一个域名、一个导航和一个设计系统：

```text
企业首页
├── 客户与销售
├── 采购与供应商
├── 商品与库存
├── 财务与税务
├── 费用报销
├── 项目协作
├── 人事工资
├── AI 助手
└── 企业设置
```

不显示 ERPNext/Framework 应用选择器，不使用 iframe，不建立第二套登录和导航。

### 9.2 小白模式与高级模式

小白模式按“我要导入流水、开销售单、采购、出入库、报销、发工资、做本月账、准备报税材料”组织任务，只显示必要字段。

高级模式提供完整字段、批量修改、会计科目、成本中心、工作流、权限、报表和导入导出。两种模式共享数据和权限。

### 9.3 导航和状态

- 主流程固定上一步、保存、下一步和提交审批；
- 所有列表支持筛选、分页、全选本页、全选结果和批量操作；
- 蓝色表示处理中，绿色完成，橙色关注，红色阻断，灰色未开始/取消；
- 状态必须同时显示文字；
- 状态包含当前原因、负责人、下一步和是否可撤销。

### 9.4 中文和错误

建立统一中文术语表。用户不得看到 Traceback、SQL、`has_permission`、容器路径和原始 500。

用户错误必须包含：操作未完成、可理解原因、数据是否变化、解决办法和错误编号。完整技术错误只进入受控日志。

### 9.5 手机端

手机端优先支持首页、审批、拍照上传、报销、客户跟进、库存查询、工资条和 AI。复杂总账、批量导入和系统配置以电脑端为主。

## 10. AI 架构

```text
业务页面
→ AI 网关
→ 权限校验和数据脱敏
→ 国内模型适配器
→ 结构化建议
→ 用户确认
→ ERP 正常业务服务和审批
```

首版 AI 能力：操作问答、单据解释、分类建议和经营摘要。

约束：

- ERP 不调用 AI 也能完整运行；
- AI 不直接写 GL Entry、库存余额、付款和工资结果；
- 写操作只能生成草稿；
- 记录模型、提示词版本、输入摘要、费用、结果和确认人；
- 每客户独立开关和额度；
- 默认禁止使用客户数据训练模型；
- 模型故障或欠费只关闭 AI。

## 11. 平台运营后台

平台后台只供运营人员使用：

- 客户、试用、站点和域名；
- 套餐、额度、到期和停用；
- 部署、升级、回滚和迁移；
- 备份、恢复、健康和任务队列；
- AI 模型、额度和成本；
- 连接器状态；
- 公共科目和行业模板；
- 帮助、公告、客服工单和安全事件。

8 周首版只实现受控站点创建、初始化、版本、备份、健康、停用和迁移。自助注册、支付和自动开通在试点后实现。

## 12. 生产部署与预算

### 12.1 试点资源

- 腾讯云广州；
- Linux 4 核 8GB、约 120GB SSD；
- Docker Compose；
- 3–5 个隔离 Site；
- 腾讯云 COS 加密备份；
- 独立预发布 Site；
- 普通客户通过 HTTPS 浏览器访问，不需要 WireGuard；
- WireGuard 或 SSH 密钥仅供受控运维。

### 12.2 月度预算目标

| 项目 | 预算估计 |
|---|---:|
| 云服务器 | 约 210–230 元 |
| COS 与附件 | 约 10–40 元 |
| 域名摊销 | 约 5–15 元 |
| 邮件、短信、通知 | 约 0–50 元 |
| 监控 | 优先开源免费方案 |
| 资源预留 | 约 50–100 元 |
| 合计 | 约 275–435 元/月 |

价格以采购当日官方页面为准，不含 AI、第三方平台和独立服务器费用。

### 12.3 网络边界

公网只开放 80/443。SSH 只允许固定 IP 或管理网络；数据库、Redis、Worker、Docker API 和内部监控不得公网开放。SSH 只使用密钥，禁止 root 密码远程登录。

## 13. 备份、恢复与监控

### 13.1 备份

- 数据库每 6 小时；
- 数据库和文件每日完整备份；
- 升级前强制完整备份；
- 本地保留 2 天；
- COS 保留 7 个日备份、4 个周备份、3 个月备份；
- 上传 COS 前加密。

试点设计目标：RPO 6 小时、RTO 4 小时。只有真实恢复演练通过后才能对外承诺。

### 13.2 监控

监控可用性、证书、5xx/502、CPU、内存、磁盘、数据库、Redis、Worker、任务队列、定时任务、备份、登录异常和 AI 费用。

### 13.3 恢复演练

每月选择测试 Site 恢复到非生产环境，验证账号、附件、业务单据、总账和报表，并记录恢复时间。

## 14. 安全与合规

### 14.1 数据安全

- 全程 HTTPS；
- 密码使用安全哈希；
- 密钥和备份密钥单独管理；
- 生产数据不得直接进入开发环境；
- 敏感导出文件设置有效期；
- 用户停用后按合同保留、导出和删除；
- 技术支持访问需要授权和审计。

### 14.2 公网手续

正式上线前完成或确认：

- 企业主体和域名实名认证；
- ICP 备案；
- 经营性互联网信息服务许可适用性；
- 公安联网备案适用性；
- 隐私政策、用户协议、数据处理协议；
- 网络安全等级保护定级；
- 开源许可证边界；
- AI 和第三方接口数据处理条款；
- 财税责任声明。

首版不声称已经完成法定税务申报，也不声称替代会计师、税务师或代账机构责任。

## 15. 测试策略

### 15.1 原则

- 开发前定义业务验收场景；
- 金额、库存、权限和租户隔离测试先行；
- 小 UI 改动只运行相关检查；
- 大模块结束运行模块回归；
- 里程碑和发布前运行完整主链路、安全、性能和恢复验收；
- 每个线上缺陷增加对应回归用例。

### 15.2 十二条端到端主链路

1. 创建客户 Site 和企业初始化；
2. 创建成员、修改临时密码和按权限登录；
3. 导入银行/微信/支付宝/发票文件；
4. 识别并确认重复，不计入待过账；
5. 自动分类、凭证、审核过账和总账；
6. 报价、订单、发货、发票和收款；
7. 采购订单、收货、采购发票和付款；
8. 入出库、调拨、盘点和库存总账；
9. 报销、审批、付款和凭证；
10. 考勤、工资、工资条、付款和凭证；
11. 结账、财务报表和报税材料；
12. 整站备份、异地恢复和业务验证。

### 15.3 财务正确性

借贷必须平衡；业务金额等于凭证；总账等于已过账分录；明细汇总等于总账；应收应付、银行、库存和工资与对应会计记录一致；冲销和删除可追溯。

### 15.4 隔离测试

验证跨域名、篡改 Site/文档编号、私有附件、API、数据库账号、备份和运营权限。任何隔离测试失败均阻断发布。

### 15.5 文件识别

系统不承诺任何格式 100% 识别。必须做到：可识别时给出依据；不确定时人工确认；失败时说明原因；不静默丢记录；导入总数、成功、跳过和失败可以对账。

### 15.6 缺陷等级

- P0：数据丢失、跨租户、账目不平、全站不可用；
- P1：主链路阻断、关键权限错误、恢复失败；
- P2：有替代方式的功能问题；
- P3：低频文案和样式问题。

发布前 P0/P1 必须为零。

## 16. 8 周里程碑

### 第 1 周：基线

资产清点、版本锁定、黄金账套、测试骨架、术语表和统一导航原型。

### 第 2 周：租户和外壳

独立 Site、初始化、域名、统一入口、角色首页、成员权限、备份和健康检查。完成 M1。

### 第 3 周：智能导入

文件识别、对账、重复复核、分类、凭证、批量审核和错误重试。

### 第 4 周：财务税务

小企业会计准则、期初、账簿、报表、结账、报税材料和正式数据受控维护。完成 M2。

### 第 5 周：销售采购库存

销售、采购、库存、应收应付和总账联动。

### 第 6 周：CRM、项目、报销、HR

复用原生模块完成 CRM、项目、报销、员工、考勤和工资。完成 M3。

### 第 7 周：AI 和运维

可关闭 AI 网关、国内模型、配额、监控、备份、恢复和回滚流程。

### 第 8 周：验收上线

冻结功能，执行主链路、隔离、财务、性能、恢复和回滚验收，修复 P0/P1，分批接入 3–5 家试点。完成 M4。

## 17. 开发治理

### 17.1 Git

使用 `main`、短期 `feature/*`、里程碑 `release/*` 和可回滚 tag，不采用复杂 Git Flow。

### 17.2 在制限制

同一时间只推进一个主要模块。每个模块遵循：验收条件 → 实现 → 相关测试 → 模块验收 → 合并。

### 17.3 验收节点

用户集中验收 M1、M2、M3、M4；中间小改动由自动测试和开发自检负责。

### 17.4 变更控制

- 主链路阻断需求进入当前版本；
- 影响试点的需求需要替换等量工作；
- 非必要优化进入后续迭代；
- 新模块单独立项。

## 18. 商业模式与套餐假设

收入来自 SaaS 订阅、托管运维、初始化迁移、专属服务器、付费连接器、AI 额度、高级支持和行业模板。

试点后的待验证价格：

| 套餐 | 建议价格 | 范围 |
|---|---:|---|
| 邀请试用 | 30–60 天免费 | 完整 MVP，限制存储和 AI |
| 基础版 | 约 199 元/月或 1990 元/年 | 财务、销售、采购、库存、报销 |
| 成长版 | 约 399 元/月或 3990 元/年 | 增加 CRM、项目、人事工资和报表 |
| 专业版 | 约 699 元/月或 6990 元/年 | 高级审批、连接器和优先支持 |
| 专属版 | 约 1299 元/月起 | 独立云资源、备份和升级窗口 |

价格必须根据试点的服务器、支持、AI、存储、迁移和客户支付意愿重新核算，不在试点前正式发布。

## 19. 试点退出条件

满足以下条件后才开放自助注册：

- 至少 3 家企业连续真实使用 4 周；
- 至少 2 家完成一次月末结账；
- 无跨租户和数据丢失事件；
- 备份恢复通过；
- 核心主链路无 P0/P1；
- 客户能独立完成大部分日常操作；
- 单客户支持成本可控；
- 隐私、服务和数据退出协议完备；
- 价格覆盖基础设施和维护成本。

## 22. 最终验收标准

邀请制版本只有在以下条件全部满足时才可发布：

- 3–5 家独立 Site 可创建、停用、备份、恢复和迁移；
- 账号、临时密码、角色和只读权限可用；
- 智能导入到正式总账主链路完整；
- 销售、采购、库存、报销和工资与财务正确联动；
- 小企业会计准则主要账簿、报表和报税材料可生成；
- 跨租户测试全部通过；
- 黄金账套核对通过；
- 备份恢复和升级回滚通过；
- P0/P1 为零；
- 统一中文主流程无应用选择器、空白页和原始技术错误；
- 监控、告警和客户支持入口可用；
- 已知 P2/P3 有清单、影响和处理计划；
- 至少一家真实企业完成初始化和首月数据导入。
