# SelfLedger 账目受控重建与永久删除设计

日期：2026-11-06  
状态：设计已口头确认，待书面复核  
适用范围：单公司、单账套、账套管理员编辑、企业成员只读

## 1. 目标

- “借贷分录”和“收支变动明细”中的同一笔账使用同一套编辑、删除服务。
- 管理员可修改交易日期、交易对象、摘要、金额、收支方向、资金账户、借方和贷方科目。
- 已过账账目不直接修改 Journal Entry 或 GL Entry；系统在一个数据库事务内撤销旧凭证、更新导入流水和草稿、重新生成正式凭证与总账。
- 删除一笔账时永久删除该笔流水及其专属附件、草稿、正式凭证、总账和关联记录。
- 任一步失败时整体回滚，不允许部分页面已更新而其他页面仍保留旧数据。

## 2. 编辑范围与页面

会计中心的“借贷分录”和“收支变动明细”每行均显示：

- 编辑整笔账目
- 永久删除

两个入口打开同一个编辑面板，字段包括：

- 交易日期与记账日期
- 交易对象
- 摘要
- 收支方向
- 业务分类
- 金额
- 资金账户
- 借方分录：科目与金额
- 贷方分录：科目与金额
- 现有标题、备注和附件

当前只修改标题、备注和附件的编辑器并入该面板，不再作为“编辑账目”的唯一内容。企业成员只能查看，不显示写操作。

## 3. 受控重建

新增管理员专属服务，以流水为唯一业务入口：

1. 锁定 Imported Transaction、Voucher Draft、Posting Link 和对应 Journal Entry。
2. 校验当前记录属于当前账套且尚未冲销。
3. 校验日期、科目、金额、方向和借贷平衡。
4. 取消并删除旧 Journal Entry 及其 GL Entry，移除旧 Posting Link。
5. 更新 Imported Transaction 的日期、交易对象、摘要、金额、方向和资金账户。
6. 更新 Voucher Draft 的记账日期、摘要、业务类型、人工覆盖标记及全部借贷行。
7. 重新执行审核与过账服务，生成新的 Journal Entry、GL Entry 和 Posting Link。
8. 保留 Ledger Evidence 的标题、备注和附件，并将最新标题和备注同步到新凭证。
9. 写入审计事件，记录操作人、旧凭证号、新凭证号及“受控重建”，不记录敏感原文。

整个流程使用同一数据库事务和行锁。新凭证生成失败时，旧凭证、流水和草稿全部恢复原状。

### 3.1 校验规则

- 借方总额必须等于贷方总额，且等于流水金额。
- 金额必须大于零并符合币种精度。
- 科目必须有效、未冻结、属于当前公司并允许记账。
- 记账日期必须属于有效会计年度，且不在冻结或关闭期间。
- 收入和支出的资金方向必须与资金账户分录一致。
- 修改关键字段后重新计算去重键；若与另一笔现存流水冲突，拒绝保存并提示先处理重复项。
- 已冲销凭证不允许重建，只能查看其历史。

## 4. 永久删除

永久删除服务按以下顺序在同一事务内执行：

1. 锁定并校验该笔流水及全部关联记录。
2. 若已过账，取消并删除 Journal Entry、GL Entry 和 Posting Link。
3. 删除该流水的 Ledger Evidence 及其私有附件文件。
4. 删除 Voucher Draft 及其分录行。
5. 清理指向该流水的重复审核关联；不得留下悬空的 duplicate_of。
6. 删除 Imported Transaction。
7. 写入独立的删除审计摘要，记录被删除业务标识、操作人、时间和原因；审计摘要不得包含银行账号或附件内容。

原始银行、微信或支付宝导入文件属于整个导入批次。只要该批次仍有其他流水，就保留共享原文件；删除该批次最后一笔流水时，才删除对应 Internal Ledger Source File、物理私有文件及空 Import Batch。这样既满足最终永久删除，也不会误删其他账目的共同来源。

删除必须二次确认并填写原因。删除完成后，该笔账立即从导入流水、待办中心、借贷分录、收支变动明细、正式凭证和总账中消失。

## 5. API 与权限

- 新增“读取整笔账编辑数据”“受控重建”“永久删除”三个最小接口。
- 服务端根据会话用户和当前账套重新查找所有对象，不接受客户端传入公司、凭证号或总账行作为权限依据。
- 仅 Administrator 和账套管理员可写；账务查看者只有读取权限。
- 原生 Journal Entry 和 GL Entry 仍禁止绕过服务直接修改或删除。
- 所有写接口仅接受 POST，并继续使用现有 CSRF、角色和公司隔离机制。

## 6. 并发与错误处理

- 编辑面板携带版本标识；他人已修改时拒绝覆盖并要求刷新。
- 服务端按固定顺序加锁，减少死锁；死锁只对完整事务做有限重试。
- 失败信息使用中文并指出具体字段，不向页面返回堆栈或内部权限钩子名称。
- 删除和重建成功后统一刷新会计中心及工作流数量，不依赖浏览器手工返回。

## 7. 非目标

- 不允许直接在浏览器中编辑 GL Entry。
- 不修改企业成员只读边界。
- 不自动学习本次人工修改为分类规则；需要学习时仍使用现有“记住规则”功能。
- 不重构无关导入、重复识别、成员管理或 ERP 模块。

## 8. 验收标准

- 从借贷分录编辑一笔已过账账目后，Imported Transaction、Voucher Draft、新 Journal Entry 和 GL Entry 的日期、摘要、金额与科目一致，旧正式凭证和旧总账行不存在。
- 从收支变动明细编辑同一笔账，返回借贷分录时显示相同的新结果。
- 借贷不平、冻结科目、关闭期间、重复键冲突和并发旧版本均被拒绝，且旧账完整保留。
- 在重建过程模拟失败后，旧流水、草稿、凭证和总账均未发生变化。
- 从任一视图永久删除后，该笔专属流水、证据附件、草稿、正式凭证和总账全部不存在。
- 共享导入文件在批次仍有其他流水时保留；最后一笔删除后，空批次及其源文件被删除。
- 企业成员不能调用重建或删除接口。
- 页面两个视图均提供编辑和永久删除，且操作成功后同步刷新，不再只打开标题备注编辑器。
- 相关后端、前端、权限和部署回归测试通过后才允许切换生产镜像。
