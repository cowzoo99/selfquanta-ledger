# 银行回单与支付截图自动入账设计

## 目标

在现有“协同内账”导入页中，管理员上传银行 PDF、微信截图、支付宝截图或原有 CSV 后，系统在本机完成文字识别和字段提取，生成可编辑的流水预览，并在管理员确认后才保存。原始资料不发送到第三方 OCR 服务。

## 首版范围

- 支持 PDF、JPG、JPEG、PNG、CSV，单文件最大 10 MiB。
- 来源可选“自动识别、银行、微信、支付宝”；默认自动识别。
- PDF 每页最多生成一笔流水；一份多页 PDF 可一次生成多笔。
- 提取时间、金额、收支方向、交易对象、摘要、流水号，并保留页码或图片序号。
- 资金科目仍由管理员选择；首版不根据银行卡尾号自动绑定科目。
- 提取结果先进入预览；缺失关键字段或置信度不足的行显示错误，不能确认导入。
- 保留既有 CSV 导入、去重、分类规则、凭证草稿与人工审核流程。

## 处理流程

1. 浏览器上传文件和可选来源提示。
2. 后端校验扩展名、实际文件类型和大小。
3. PDF 优先提取文字层；文字不足时逐页渲染并 OCR。图片直接 OCR。
4. 自动识别文档来源，再由银行、微信或支付宝解析器提取字段。
5. 返回流水、识别警告和文件哈希；管理员在中文预览页核对。
6. 管理员确认后，系统重新解析并校验哈希，再保存原始私有文件和流水。
7. 现有规则提出借贷分类建议，仍需人工复核后过账。

## 部署边界

OCR 使用 CPU 版 RapidOCR，作为仅加入 Docker 内部网络的小服务运行，不发布宿主机端口。ERPNext 后端通过内部 HTTP 调用它。PDF 文字层由 pypdf 读取；OCR 服务负责图片和无文字层页面。服务不可访问公网业务接口，也不保存上传内容。

## 安全与失败处理

- 真实账单、截图、账号、交易号和 OCR 输出不得进入 Git、普通日志或测试夹具。
- 原始文件沿用现有私有附件权限；只允许账套管理员导入。
- 不确定结果必须停止在预览，不猜金额、方向或时间。
- OCR 服务不可用时返回明确中文错误，不降级为自动过账。
- 确认导入仍使用文件哈希和既有去重键，避免预览后文件被替换或重复入账。

## 验收标准

- 用户提供的 8 页浙江稠州商业银行 PDF 生成 8 笔预览，各页的时间、金额、付款/收款方、用途和流水号可核对。
- 用户提供的支付宝截图生成 1 笔 `11.40` 元支出，时间和“高德打车”摘要可核对。
- 用户提供的微信截图生成 1 笔 `78.00` 元支出，时间、交易对象和商品摘要可核对。
- 三份文件共形成 10 笔预览；未点击“确认导入”前数据库中不新增流水。
- 查看者不能上传或确认；管理员可以修正预览中的可编辑字段后确认。
- 中文工作台直接显示“文件智能导入”，不要求用户进入 ERPNext 英文 Setup 页面。

## 明确不做

首版不做发票识别、税务判断、云 OCR、手机端自动抓取、银行直连、无人审核自动过账，也不承诺识别任意银行或任意版本支付页面。
