# SelfLedger 事件响应

## 恢复目标

- 备份恢复点目标（RPO）：24 小时。
- 试运营恢复时间目标（RTO）：4 小时。RTO 从确认需要恢复开始，到隔离恢复验证通过并恢复受控流量为止。

## 严重级别

- **P0**：跨企业数据可见、密钥泄露、不可逆数据破坏或全部 Site 无法使用。立即停止相关流量，保全日志，通知负责人和受影响客户。
- **P1**：单个企业无法使用、备份连续失败或账务主链路错误。暂停该 Site 的写入和新客户开通，当日处理。
- **P2**：有绕行方案的功能故障。进入计划修复，不直接热改容器或数据库。
- **P3**：文案、布局或低影响体验问题。进入版本排期。

## 处理顺序

1. 记录发现时间、Site、版本 SHA 和影响范围，不复制业务正文到公共工单。
2. 需要隔离时只对目标 Site 进入维护模式；不要停止其他企业。
3. 检查 HTTPS、证书、队列、调度器、最近加密备份和审计记录。
4. 按备份清单在全新 `ledger-restore-*` 项目中恢复，验证通过后再决定切换或回滚。
5. P0/P1 在确认影响后尽快通知客户，说明影响范围、临时措施、下一次更新时间和恢复结果；不猜测原因。

## 凭据轮换

发生疑似泄露时，依次轮换模型 API 密钥、备份密钥、COS 凭据、数据库/root 密码、Site 管理员密码和 TLS 私钥。新凭据只写入受限文件或密钥服务，不进入命令行、Git、聊天记录或日志。轮换后执行登录、备份、恢复和审计验证；确认新凭据生效后再吊销旧凭据。
